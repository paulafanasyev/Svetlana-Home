# Local AI

## Главное правило (ТЗ §87)

> Светлана может обнаружить подходящую локальную модель, проверить её
> совместимость и предложить пользователю установить её. Но Светлана
> **никогда** не должна самостоятельно скачивать или устанавливать
> локальную AI-модель без явного решения пользователя.

Это правило распространяется на любые крупные AI-ресурсы: LLM, VLM,
TTS, STT, avatar models, embeddings (ТЗ §33).

## Сценарий предложения (ТЗ §32)

```
Светлана:
Я нашла локальную модель, совместимую с вашим устройством.

Название: ...
Размер: ...
Требуется памяти: ...
Ожидаемая производительность: ...

[Скачать]  [Подробнее]  [Не сейчас]
```

Только после явного решения начинается загрузка.

## Состояние после установки

> «Нет локальной модели» — это нормальное состояние приложения (ТЗ §64).

Launcher, Hands, голос, реестр приложений
работают и без локального ИИ.

## Управление моделями (ТЗ §34)

Раздел «Локальный ИИ» показывает: `Установленные`, `Совместимые`,
`Доступные`.

Для установленной модели: `Использовать`, `Остановить`, `Проверить`,
`Запустить benchmark`, `Удалить`, `Сделать основной`.

## Реализация

- `AIModelRegistry` — метаданные моделей (см. `model-registry.md`).
- `AIModelCompatibilityEngine` — оценка совместимости (см.
  `model-compatibility.md`).
- `LocalModelManager.install(model)` — начинает загрузку **только** по
  вызову из UI после тапа пользователя на «Скачать».
- `BenchmarkRunner.run()` — фактические измерения (см. ниже).
- `LocalAIProvider` — провайдер для AI Router.

## Inference runtime

Реальный вывод выполняется через `InferenceRuntime`. Runtime'ов два,
и выбор определяется форматом выбранной модели — диспетчером служит
`CompositeInferenceRuntime`.

| Параметр | llama.cpp | LiteRT-LM |
|----------|-----------|-----------|
| Библиотека | `dev.ffmpegkit-maintained:llama-android:0.1.1` | `com.google.ai.edge.litertlm:litertlm-android:0.17.1` |
| Лицензия | MIT | Apache-2.0 |
| Архитектура | `arm64-v8a` (CPU/NEON) | arm64-v8a / x86_64 |
| Формат моделей | GGUF | **.litertlm** |
| Multimodal | Нет | **Да (image/audio)** |
| Backends | CPU | CPU / GPU / NPU |
| Назначение | text-fallback | **основной multimodal runtime** |

Runtime'ы поставляются в составе APK (нативные библиотеки внутри AAR).
Это не нарушает правило «никаких скрытых загрузок»: библиотека — это
**код**, а не AI-модель. Сами файлы моделей по-прежнему скачиваются
только после явного решения пользователя.

### LiteRT-LM (аудит §10-12, P0-1)

`LiteRtLmRuntime` — мультомодальный on-device inference,
Google AI Edge: https://github.com/google-ai-edge/LiteRT-LM (Apache-2.0)

- **vision** — изображение передаётся в модель через `Content.ImageBytes`,
  а не игнорируется (это и было ядром BLOCKED Vision);
- **vision-поддержка определяется самой моделью** через
  `Capabilities.inputModalities().vision` — мы не декларируем её за неё;
- **tool use** (`@Tool` / `@ToolParam`) — для действий на устройстве;
- CPU backend по умолчанию (GPU требует нативные библиотеки в манифесте,
  NPU — vendor-библиотеки; оба требуют device-проверки).

Модели (.litertlm) доступны на HuggingFace LiteRT Community —
пользователь выбирает и скачивает сам.

### llama.cpp

`LlamaCppRuntime` — text-fallback для GGUF-моделей:

- загружает GGUF в нативную память по запросу (`isReady()`);
- сериализует вызовы (LlamaModel не потокобезопасен);
- выставляет `contextSize` из реестра модели и число потоков по числу ядер;
- сообщает фактические tokens/sec и задержку, которые использует
  `BenchmarkRunner`;
- выгружает модель по команде «Остановить» (ТЗ §34).

Если устройство не arm64 — нативный слой недоступен, и провайдер
честно отвечает «нативный llama.cpp недоступен на этом устройстве»,
не пытаясь симулировать inference.

### LOCAL_ONLY vision

`LocalAIProvider.vision()` — единственный путь зрения, не покидающий
устройство. Включается, только если активная модель сама сообщает
vision-модальность; иначе честный отказ с указанием, какую модель
нужно установить.

## Проверка модели после установки (аудит п.2)

«Установлена» ≠ «работает». После загрузки интерфейс автоматически
запускает `ModelVerificationRunner.verify()`, который проходит реальную
цепочку и показывает результат каждого этапа:

```
✓ Файл найден            1838 МБ
✓ Совместимость          Q4_K_M, контекст 4096
✓ Runtime                llama.cpp готов
✓ Load                   модель загружена в память
✓ Context                контекст создан
✓ Inference              ответ получен

Первый токен: 2.8 сек
Скорость: 4.1 ток/с
RAM: 3200 МБ
```

Если inference не запущен, интерфейс показывает **причину**, а не
«установлено»:

```
✓ Файл найден            1838 МБ
✕ Runtime                недоступен на этом ABI
✕ Load                   runtime недоступен
✕ Inference              runtime недоступен

✕ Inference не запущен
Причина: runtime недоступен
```

Та же проверка доступна вручную кнопкой «Проверить модель» в разделе
«Локальный ИИ».
