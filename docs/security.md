# Security (ТЗ §57–§59)

## Строго запрещено

- root;
- Termux;
- произвольный shell;
- скрытые команды;
- скрытая установка моделей;
- скрытая установка приложений;
- обход Android permissions;
- обход Accessibility;
- скрытое управление;
- автоматическое подтверждение опасных действий.

## Реализация запретов

1. **Нет shell execution.** В приложении нет `Runtime.exec()`,
   `ProcessBuilder` и подобных вызовов ни в одной точке кода.
2. **Закрытый набор действий.** `SvetlanaAction` — sealed class.
   Модель не может сгенерировать произвольную команду: разрешены только
   перечисленные действия (`OpenApp`, `Click`, `TypeText`, ...).
3. **Нет скрытых загрузок.** Единственный путь установки модели —
   `LocalModelManager.install()`, который вызывается только из UI после
   тапа пользователя на «Скачать» (ТЗ §32, §33, §87).
4. **Accessibility не включается сам.** Сервис декларируется в манифесте,
   но включается только пользователем через системные настройки.
5. **Опасные действия подтверждаются.** `AppControlEngine.riskOf()`
   возвращает `DANGEROUS` для звонков и сообщений; `ActionRouter`
   возвращает `requiresUserConfirmation`, UI показывает диалог.

## Хранение секретов

- API-ключи провайдеров и токены сервера — в `SecureKeyStore`
  (AndroidX Security, AES-256-GCM, мастер-ключ в Android Keystore).
- Секреты **не попадают** в репозиторий, логи, аналитику.
- `AIProvider.redactedConfig()` всегда печатает ключ как `скрыт`.
- Backup в облако отключён (`allowBackup=false`,
  `fullBackupContent=false`, `dataExtractionRules` исключают всё).

## Верификация владельца

- Android Keystore (hardware-backed, где доступно);
- системный диалог биометрии/PIN/пароля;
- PIN/пароль пользователя никогда не сохраняются и не запрашиваются
  приложением (ТЗ §23).

## Статусы безопасности

- root: нет
- Termux: нет
- shell execution: нет
- обход permissions: нет
- скрытые загрузки: нет
- скрытое управление: нет
- автоподтверждение опасных действий: нет

## Ограничения приложений (ТЗ §67)

Если приложение не предоставляет Intent, блокирует Accessibility,
требует собственное подтверждение или не позволяет автоматизацию,
Светлана сообщает: «Это действие недоступно через Android или ограничено
самим приложением» — и не пытается обойти ограничение.
