# Voice

## Wake words (ТЗ §21)

`Света`, `Светочка`, `Светлана`.

`WakeWordEngine` слушает короткие окна распознавания, и распознанный
текст проверяется на слово пробуждения **полностью локально** — голос
не покидает устройство. Логика сопоставления вынесена в `WakeWordMatcher`
(чистая функция, покрывается unit-тестами).

Цикл wake word активен только если пользователь включил его в
настройках и предоставил разрешение на микрофон.

### Ограничение: это не always-on детектор

Текущая схема — **STT polling**: системный распознаватель опрашивается
короткими окнами (~4с). `WakeWordEngine.listeningKind` явно возвращает
`STT_POLLING`. Это:

- расходует больше батареи, чем аппаратный low-power детектор;
- не работает в Doze, когда экран выключен;
- не является «настоящим» always-on wake word engine.

Пользователь видит честное описание в настройках. Полноценный
low-power детектор требует интеграции с аппаратным DSP — это пункт
roadmap, а не заявленная возможность.

## STT

`SvetlanaSpeechRecognizer` — системный распознаватель Android
(`SpeechRecognizer`) с языком `ru-RU`.

Если на устройстве нет распознавателя (например, без GMS),
приложение честно сообщает «Распознавание речи недоступно» и
продолжает работать через текстовый ввод.

## TTS

`SvetlanaTts` — системный `TextToSpeech` с языком `ru-RU`.
Озвучивает ответы Светланы.

## Архитектура

```
Wake word (Света)
↓
STT (ru-RU)
↓
CommandParser
↓
ActionRouter / AIRouter
↓
Результат
↓
TTS (ru-RU)
```

## Диалог

Если команда не является управлением устройством, она уходит в
AI Router (локальная модель / персональный сервер / внешний провайдер)
с учётом персональной памяти (если режим памяти это разрешает).

## Фоновый голосовой ассистент

`VoiceAssistantService` — foreground-сервис с типом `microphone`.
Цикл прослушивания слова пробуждения живёт в сервисе, поэтому
Светлана слышит команды, даже когда приложение свёрнуто.

```
Микрофон (foreground, тип microphone)
↓
WakeWordEngine (STT_POLLING)
↓
Слово пробуждения обнаружено
↓
VoiceAgent.handle()
↓
Action Router → AI Router
↓
Голосовой ответ (TTS)
```

В сервисе нет скрытого доступа к микрофону:

- foreground-сервис виден пользователю через постоянное уведомление;
- у уведомления есть кнопка «Стоп»;
- сервис стартует только если пользователь включил wake word в
  настройках и выдал разрешение на микрофон;
- после перезагрузки `BOOT_COMPLETED` не запускает microphone foreground-service автоматически:
  современные версии Android ограничивают такой фоновый запуск;
- роль главного экрана сохраняется системой, а фоновый голосовой сервис запускается
  снова из видимой пользовательской сессии, когда соблюдены условия доступа.

### Единое ядро диалога

`VoiceAgent` — единственный исполнитель команд и для экрана, и для
фонового сервиса. Поэтому поведение диалога одинаково:

- те же команды `CommandParser`;
- тот же privacy-роутинг `PrivacyRouter` / `PrivacyPolicy`;
- тот же выбор провайдера `AIRouter`;
- тот же голосовой отклик `SvetlanaTts`.

### Мгновенный голосовой отклик

Требование: «голос должен начинать говорить сразу, даже пока ответ
полностью не получен».

1. При обращении к ИИ `VoiceAgent` немедленно произносит filler-фразу
   («Дай подумать…», «Сейчас…», «Минуточку…») — пользователь слышит
   отклик до получения ответа.
2. `AIRouter.chatStream` стримит ответ (SSE для OpenAI-compatible
   провайдеров). Как только первая порция готова, TTS прерывает filler
   и начинает говорить суть.
3. Для провайдеров без стриминга filler звучит, пока не придёт полный
   ответ — пауза заполнена, молчания нет.

### Подтверждение опасных действий из фона

ТЗ §58: отправка сообщения — опасное действие. Если пользователь
дал команду «напиши контакту…» в фоне, `VoiceAgent` не выполняет её
автоматически. Светлана произносит: «Открываю приложение для
подтверждения» — и открывает главный экран, где пользователь явно
подтверждает действие. **Обхода Android security model нет.**
